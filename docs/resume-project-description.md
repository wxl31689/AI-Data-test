# 简历项目描述

## 一句话版本

独立设计并开发 AI 辅助接口测试与数据质量分析平台，打通 OpenAPI 导入、批量执行、断言证据、CSV/XLSX 质量检测、清洗导出、HTML 报告与可审计 AI Agent 闭环。

## 简历项目经历

**TestData Agent AI Agent｜全栈/测试开发个人项目**
技术栈：Vue 3、TypeScript、Element Plus、Spring Boot 3、Java 21、REST Assured、JPA、H2/MySQL、OpenAI Responses API

- 设计异步批量测试引擎，支持幂等创建、单用例故障隔离、失败重跑、6 类断言和结果快照；10 条端到端用例稳定产出 9 PASS/1 可复现预期 FAIL，并生成 90% 通过率 HTML 报告。
- 实现受限 CSV/XLSX 数据管道，覆盖必填、重复、类型和范围规则，以及非破坏式清洗预览和双格式导出；演示数据可定位 6 个质量问题、2 个清洗单元格和 1 条重复记录。
- 基于 Responses API 严格结构化输出实现用例生成，候选仅能以 `AGENT / DRAFT` 保存，保留人工审核边界。
- 设计 `execute_test_run` 与 `get_test_run_evidence` 两类受控工具，执行参数精确绑定人工授权、用例版本和审核记录；幂等防重、异步状态与工具审计落库，分析逐条校验真实 resultId，保留测试引擎最终判定。
- 建立 54 项后端测试、4 项演示 API 测试和端到端脚本；本轮另有 24 项隔离协议替身检查，覆盖超时、非法输出、认证错误、权限、幂等、证据关联和模型不可用时核心功能降级。

验收边界：已实现 Responses API 适配并通过本机协议替身验证；真实模型成功调用及完整人工模型流程仍待授权验收。简历与面试不得将替身结果表述为已完成真实模型效果评估。MySQL 有配置与 Schema，本轮实际冷启动及运行验证使用 H2。

## 面试展开点

1. 为什么不让 LLM 直接判定 PASS/FAIL：不可复现且容易被提示注入；项目用规则引擎保存事实，Agent 只做建议与解释。
2. 如何限制工具调用：服务端注册表、严格 Schema、执行审批/用例版本绑定、分析 runId 绑定、原测试引擎、受限等待、幂等和持久化审计。
3. 如何避免“演示数据造假”：演示 API、端到端脚本、预期失败用例和报告都可在本地复现，失败仍计入 90% 统计。
4. 下一步：真实模型和人工端到端验收、最终交付；JWT/RBAC、调用配额、队列化执行、Docker Compose、PDF 报告和 CI 为可选后续增强。
